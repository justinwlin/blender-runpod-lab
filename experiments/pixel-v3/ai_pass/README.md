# Pixel v3: AI realism pass (ComfyUI)

Goal: make the rendered Pixel read as a soft, fluffy mini toy kitten instead of smooth vinyl, using the Blender render only for motion, pose, camera and the calico patches, and keeping the set and props exactly as rendered.

**Status: work in progress.** A 4-second test shot is being tuned; the full 26 s has not been run. Nothing here is a finished result yet.

- [MODELS.md](MODELS.md): every model, LoRA and node with links, revisions, sizes, target folders and licences
- [setup_comfy.sh](setup_comfy.sh): installs ComfyUI, the two custom nodes and the models on a pod (`wan`, `sdxl` or `all`)
- [make_workflows.py](make_workflows.py): generates the API-format workflows from parameters (seed, denoise, ControlNet strengths, LoRA weight, paths)
- [run_workflow.py](run_workflow.py), [run_frames.py](run_frames.py): queue a workflow on the local ComfyUI server and wait; the second runs one prompt per frame
- [depth_pass.py](depth_pass.py), [matte_pass.py](matte_pass.py): Blender scripts that render an exact depth pass and a cat matte from the film scene
- [composite.py](composite.py): puts the AI cat back over the untouched render through the matte
- [api_to_ui.py](api_to_ui.py): converts an API workflow to UI-format JSON
- [workflows/](workflows/): one folder per test with the workflow that was run

## About the workflow files

- `*.api.json` is the artefact that was run. The four Wan tests (`t1`-`t4`) are the exact files that were queued on the pod. The SDXL tests were queued from temporary files that were not kept, so theirs are regenerated by `make_workflows.py` from the recorded parameters (`params.json`): same graph and values, not the same bytes.
- `*.ui.json` is produced by `api_to_ui.py`, **not exported from the ComfyUI editor, and has not been opened in the editor** (there is no browser on the build box). If one does not load, drag the `.api.json` in instead; the editor opens API-format files too.
- Paths inside the workflows are pod paths (`/workspace/ai/...`, `/workspace/pc/...`).

## Tests so far (walk shot, film frames 160-240, 81 frames, 1280x720, seed 7)

| Test | Workflow | Key settings | Time on an RTX 4090 | Result |
| --- | --- | --- | --- | --- |
| `t1_refine` | `wan_vace_refine` | render encoded, re-noised from step 2 of 4 (about 50%), low-noise model + lightx2v, VACE depth 1.0 + canny 0.7 | 240 s | **Failed.** Looks the same as the render, no fur |
| `t2_full` | `wan_vace_full` | full generation, two chained VACE controls (depth 1.0, canny 0.7) + a reference frame, high then low, 4 steps | 358 s | **Failed.** Ghosted double image, garbled legs and props. Chaining two VACE controls with a reference is the suspected cause; dropped |
| `t3_refine` | `wan_vace_refine` | as t1 but re-noised from step 1 of 4 (about 75%), high then low | 268 s | **Failed.** Still smooth plastic |
| `b1_sdxl` | `sdxl_frame_refine` | per frame, denoise 0.55, FluffyStyle LoRA 0.8, depth 0.8 + canny 0.6, 22 steps | about 12 s per frame | **Failed.** No fur; stopped part-way |
| `key_k1`-`key_k4` | `sdxl_frame_refine` | single frames (200 and 490), denoise 0.75-1.0, LoRA 1.0, with and without the tile control | 9-12 s per frame | **Fur appears.** Without tile the patches drift; with tile 0.4-0.6 the patch layout mostly holds |
| `b2_sdxl` | `sdxl_frame_refine` | `key_k2` settings on all 81 frames: denoise 0.9, LoRA 1.0, depth 0.7, canny 0.4, tile 0.5 | about 12-15 s per frame | Rendered; flicker not assessed yet |
| `t4_key` | `sdxl_frame_refine` then `wan_vace_keyframe` | SDXL key frame of film frame 160 (the `b2` settings) as VACE start frame (mask 0) and reference image; remaining 80 control frames are the Blender depth pass (mask 1), VACE strength 1.0; high then low, lightx2v 4 steps, shift 5, cfg 1, euler/simple | 301 s | **First result with obvious fur**, stable across the shot, motion and camera follow the render. Repaints props and wall and shifts patches, so it needs the cat matte composite; legs look stiff |

The settings that first showed fur (`t4_key`) are in [workflows/t4_key/](workflows/t4_key/): `sdxl_frame_refine.*` makes the key frame, `wan_vace_keyframe.*` makes the video.

`composite.py` over the `t4_key` frames (matte grown 7 px, feathered 5 px) keeps the ball, books, wall and light exactly as rendered.

## What is still open

- Review asked for a cute, soft, rounded mini toy kitten rather than a furry version of the Blender shape: looser depth/line control, masked cat-only repaint, toy prompt (`sd_prompt=toy`, `matte=`). In progress.
- Legs read as stiff in the video; looser control on the legs and/or a springier Blender walk are to be tested.
- Patch fidelity against the render at high denoise.
- Per-frame SDXL versus Wan for flicker; the full 26 s; upscaling the 720p AI cat for the 1080p film.
